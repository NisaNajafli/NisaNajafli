## About

QA Engineer working on a **fintech investment platform** — microservices, Camunda BPM workflows, Oracle, Kafka. My day is requirement analysis, test design, API & UI automation, and finding the edge case that nobody wanted to think about.

I came into QA from a **development background**, which means I read the code, not just the screen. I can reproduce a defect, explain the likely cause, and hand the developer something they can actually act on.

## How I Work

- **Break requirements first, not builds.** Most defects are cheaper to catch in the spec than in QA.
- **A bug report is a deliverable.** Steps, expected, actual, environment, logs — no archaeology required.
- **Automate what repeats.** Regression suites should run while people sleep.
- **Think like the user, verify like an engineer.** Both perspectives, every release.
